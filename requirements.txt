Main Project Goals

The overall goal of Quiet Flame is to build a production-ready, scalable, secure, and responsive USA-focused candle ecommerce platform with a clean customer storefront and a protected admin management system.

1. Customer E-commerce Experience

The project can provide a complete customer journey:

Homepage
   ↓
Product Catalog
   ↓
Product Details
   ↓
Add to Cart / Buy Now
   ↓
Cart
   ↓
Checkout
   ↓
Order Validation
   ↓
Order Creation
   ↓
Order Confirmation

Customers can browse products, search and filter products, view detailed product information, manage quantities, remove products, and complete purchases.

2. Smart Cart Management

The cart can use Zustand + localStorage for a fast client-side experience while the database remains the source of truth for product information.

It can handle:

Quantity increase/decrease
Maximum quantity limits
Product removal
Clear cart
Cart persistence
Server-side cart validation
Price changes
Removed products
Inactive products
Real-time subtotal calculation
3. Secure Checkout

The checkout system can collect:

Customer Information
        +
Shipping Address
        +
Payment Method
        +
Cart Items
        ↓
Server Validation
        ↓
Order Creation

The server should never trust price, product name, subtotal, or total values coming from the browser.

4. Smart Address Autocomplete

For the USA-focused store, the checkout can provide:

User types address
        ↓
Geoapify suggestions
        ↓
User selects address
        ↓
Street Address
City
State
ZIP Code
Country
        ↓
Automatically populated

This makes checkout faster and reduces manual address entry.

5. Admin Dashboard

The admin system can act as the central business management platform.

An administrator can manage:

Dashboard
Products
Orders
Account
Settings

The dashboard can later include metrics such as:

Total orders
Revenue
Completed orders
Pending orders
Product count
Recent orders
Sales trends
6. Product Management

Admin users can:

Create Product
      ↓
Update Product
      ↓
Activate / Deactivate
      ↓
Soft Delete
      ↓
Search / Filter / Paginate

Products can contain images, descriptions, prices, compare-at prices, currency, slugs, and active status.

7. Order Management

The admin order system can support:

Order listing
Order search
Pagination
Customer information
Shipping information
Purchased items
Order totals
Payment method
Payment status
Order status
Individual order details
8. Secure Authentication and Authorization

The admin area can use:

Admin Login
    ↓
JWT / Secure Cookie
    ↓
Middleware Protection
    ↓
Server-side Authorization
    ↓
Admin Dashboard

The goal is to prevent customers and unauthorized users from accessing protected admin functionality.

9. Data Integrity and Validation

The application can use Zod + service-layer validation to ensure that data is validated before it reaches the database.

For example:

Client Validation
        ↓
Server Validation
        ↓
Business Logic
        ↓
Database

This provides multiple layers of protection instead of trusting browser input.

10. Scalable Service Architecture

Business logic is separated into services:

UI
 ↓
Server Action / API
 ↓
Service
 ↓
Model
 ↓
MongoDB

This makes the codebase easier to maintain and allows business logic to be reused by Server Actions, API routes, admin pages, and future integrations.

11. SEO and Discoverability

The project can support:

Metadata
SEO-friendly product slugs
Sitemap
Robots configuration
Product-specific pages
Search-engine-friendly public pages
Proper 404 handling

The admin and checkout areas can remain excluded from search engine indexing.

12. Responsive Design

The storefront should work across:

Mobile
Tablet
Laptop
Desktop
Large Desktop

The UI can use mobile-first Tailwind patterns so product grids, checkout forms, navigation, buttons, cart components, and admin interfaces adapt to different screen sizes.

13. Performance

The architecture is designed to take advantage of Next.js features such as:

Server Components
Client Components only where interaction is required
Image optimization with next/image
Loading UI
Server-side data fetching
Caching where appropriate
Small client-side JavaScript footprint
Database connection reuse
